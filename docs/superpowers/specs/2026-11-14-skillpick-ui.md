# SkillPick 상세 UI 명세

- 원천 설계: `2026-11-14-skillpick-design.md`
- 시안 이미지: `docs/ui/mockups/*.png` (jdmnk-codex-imagegen 생성, 분위기·배치 참고용. 문구·수치·상태는 이 문서가 정본)
- 구현: Kiro. 이 문서가 화면의 원천이다

## 0. 공통

**창**: 기본 1440×900, 최소 1200×760. macOS 기본 제목 표시줄을 숨기고(신호등 버튼만) 상단 52px을 앱 툴바로 쓴다.

**톤**: 개발자 도구. 앱 껍데기는 짙은 중립 회색이고, 사용자가 비교할 시안(밝고 다채로운 웹페이지)이 가장 눈에 띄게 한다. Figma 캔버스처럼 시안이 주인공, 앱은 액자다.

**색 토큰** (한 곳에서만 정의)
| 토큰 | 값 | 쓰임 |
|---|---|---|
| `bg` | `#0E0F11` | 창 배경 |
| `surface` | `#16181B` | 패널·카드 |
| `surface-2` | `#1E2125` | 입력칸, 눌림 |
| `line` | `#2A2E33` | 1px 구분선 |
| `text` | `#ECEDEE` | 본문 |
| `text-dim` | `#9BA1A6` | 보조 |
| `accent` | `#7C8CFF` | 주 버튼, 선택 테두리 |
| `ok` | `#3DD68C` | 통과 |
| `warn` | `#F5A524` | 경고 (지어낸 숫자 의심, 일부 누락) |
| `bad` | `#F26D6D` | 실패 |

**글꼴**: Pretendard(본문·UI), JetBrains Mono(URL·명령·로그·시간). 크기 12/13/14/16/20/28. `word-break: keep-all`.

**간격**: 4의 배수. 패널 안 여백 20, 카드 사이 16. 모서리 반경 카드 12, 버튼·입력 8. 터치 대상 최소 32px 높이(데스크톱 앱).

**문구 규칙**: 한국어, 짧게. 문장 끝 마침표 쓰지 않음. em dash 쓰지 않음. 하지 않는 일을 한다고 쓰지 않음.

**레이아웃 뼈대**
```
┌──────────────────────────────────────────────────────────────┐
│ ● ● ●  SkillPick     [단계 표시: 입력 › 확인 › 생성 › 비교]   ⚙ │ 52px 툴바
├────────────┬─────────────────────────────────────────────────┤
│ + 새 비교   │                                                 │
│            │                 본문 (단계별 화면)                │
│ 최근 비교   │                                                 │
│ · aibuild… │                                                 │
│ · lumen…   │                                                 │
│ 220px      │                                                 │
└────────────┴─────────────────────────────────────────────────┘
```
- 왼쪽 사이드바: `+ 새 비교`, 최근 실행 목록(사이트 도메인, 스킬 수, 상대 시간). 실행 중이면 점 애니메이션.
- 툴바 가운데 단계 표시: 지난 단계는 눌러 돌아갈 수 있음(생성 중에는 잠김).

## 화면 1. 준비 확인 (첫 실행, 또는 Kiro 상태가 나쁠 때만)

목적: BYOK 전제(내 Kiro CLI 로그인)를 앱이 직접 확인한다.

```
          SkillPick
          내 페이지에 디자인 스킬을 한 번에 돌려 보고 결과로 고르세요

          ┌ 준비 상태 ─────────────────────────────────┐
          │ ✓ kiro-cli 설치됨        3.1.0              │
          │ ✓ Kiro 로그인됨          tae…@…             │
          │ ✓ 동시 실행 설정         3개                 │
          └────────────────────────────────────────────┘
                         [ 시작하기 ]
```
- 항목 상태: 확인 중(스피너) / ✓ / ✗ + 해결 방법.
- 설치 안 됨: `✗ kiro-cli를 찾지 못했어요` + 설치 명령 한 줄(복사 버튼) + `다시 확인`.
- 로그인 안 됨: `✗ 로그인이 필요해요` + `kiro-cli login` 복사 + `다시 확인`.
- 모두 ✓면 `시작하기` 활성. 다음 실행부터는 이 화면을 건너뛰고 백그라운드로만 확인한다.

## 화면 2. 새 비교 (URL + 스킬 고르기)

```
┌ 어떤 페이지를 바꿔 볼까요 ───────────────────────────────────┐
│ [ https://                                       ] [불러오기] │
│  공개 페이지나 localhost 주소를 넣으세요                       │
└──────────────────────────────────────────────────────────────┘
┌ 어떤 스킬로 돌려 볼까요   3개 선택   동시에 3개씩 만들어요 ────┐
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐           │
│ │☑ frontend-    │ │☑ web-design- │ │☐ ui-ux-pro-  │           │
│ │  design       │ │  guidelines  │ │  max         │           │
│ │ Anthropic     │ │ Vercel       │ │ nextlevel…   │           │
│ │ 대담한 미감,   │ │ 접근성·관례  │ │ 스타일 50종  │           │
│ │ 뻔한 AI 느낌   │ │ 점검 중심    │ │ 지침만 적용   │           │
│ │ 피하기         │ │              │ │              │           │
│ └──────────────┘ └──────────────┘ └──────────────┘           │
│  …                                   [+ SKILL.md 주소로 추가] │
└──────────────────────────────────────────────────────────────┘
                                     [다음: 원본 확인 →]
```
- URL 입력: 모노 글꼴. 엔터 = 불러오기. 잘못된 주소면 입력 아래 빨간 한 줄 `http 또는 https 주소만 넣을 수 있어요`.
- 스킬 카드(3열 격자, 폭 자동): 체크박스, 이름(모노), 제작처, 한 줄 설명(두 줄 넘으면 말줄임), 꼬리표(`지침만 적용`, `직접 추가`). 카드 전체가 눌림 영역. 선택 시 `accent` 테두리.
- 카드 오른쪽 위 `↗`: 출처 GitHub 열기.
- 선택 0개면 다음 버튼 비활성 + `스킬을 하나 이상 골라 주세요`.
- `+ SKILL.md 주소로 추가`: 작은 대화상자. 주소 입력 → `가져오기` → 미리보기(이름·첫 3줄) → `추가`. 실패: `이 주소에서 SKILL.md를 읽지 못했어요`.
- `다음`을 누르면 원본 수집을 시작하고 화면 3으로 이동.

## 화면 3. 원본 확인 (지켜야 할 것)

목적: 시안이 무엇을 반드시 지킬지 사용자가 보고 동의한다. 데모에서 "이 14개는 어떤 스킬도 못 바꾼다"를 보여 주는 화면.

```
┌ 원본 ───────────────────────┐ ┌ 지켜야 할 것  14개 ───────────────┐
│ [데스크톱|모바일]            │ │ 모든 시안이 이 항목을 그대로 담아야 │
│ ┌─────────────────────────┐ │ │ 통과해요                            │
│ │                         │ │ │ 제목                                │
│ │   (원본 1440 캡처,       │ │ │ ☑ AI 빌더를 위한 커뮤니티            │
│ │    세로 스크롤)          │ │ │ 소제목                              │
│ │                         │ │ │ ☑ 이번 주 행사  ☑ 함께 만든 것들    │
│ │                         │ │ │ 버튼                                │
│ │                         │ │ │ ☑ 지금 참가하기 → /join             │
│ └─────────────────────────┘ │ │ 가격                                │
│ theaibuilders.dev · 2.1초    │ │ ☑ ₩0                              │
└─────────────────────────────┘ │ 내비                                │
                                │ ☐ 블로그 → /blog                    │
                                └────────────────────────────────────┘
                     [← 스킬 다시 고르기]   [시안 3개 만들기 →]
```
- 수집 중: 왼쪽에 캡처 자리 스켈레톤 + `페이지를 열고 있어요`, 오른쪽 목록 스켈레톤. 상한 20초.
- 수집 실패: 가운데 `이 페이지를 열지 못했어요` + 사유(시간 초과/차단/주소 오류) + `다시 시도`.
- 목록: 종류별 묶음(제목·소제목·첫 단락·버튼·가격·내비). 체크 해제하면 그 항목은 검사에서 뺀다. 버튼·링크는 `글자 → href`(href는 모노, 흐리게).
- 상한 25개. 줄였다면 목록 위 안내 `항목이 많아 소제목과 내비 일부를 뺐어요`.
- 원본 캡처 위에 마우스를 올리면 해당 항목을 목록에서 강조하는 연결은 하지 않는다(범위 밖).

## 화면 4. 생성 중

목적: 동시에 도는 것을 정직하게 보여 준다. 실제 상태만.

```
 theaibuilders.dev · 스킬 3개 · 동시 3개 실행 중 · 대기 0          04:12
┌ frontend-design ──────────────────────────────────────────────┐
│ ● 만드는 중   02:13                                            │
│ ▕█████████░░░░░░░▏  단계: 생성 → 검사 → 완료                     │
│ > fs_write out/index.html (18.2 KB)                            │
│ > 히어로 섹션 작성                                              │
├ web-design-guidelines ────────────────────────────────────────┤
│ ◐ 검사 중     03:40      지켜야 할 것 13/14 확인 중               │
├ ui-ux-pro-max ────────────────────────────────────────────────┤
│ ↻ 다시 고치는 중 (1/1)  05:02   빠진 항목: 가격 ₩0               │
└───────────────────────────────────────────────────────────────┘
                 [완료된 것부터 보기]          [전부 멈추기]
```
- 한 줄 = 시안 하나. 상태 배지: `대기`(회색) `만드는 중`(accent, 점 애니메이션) `검사 중` `다시 고치는 중 (1/1)`(warn) `완료`(ok) `실패`(bad) `시간 초과`(bad).
- 진행 막대는 실제 단계 3개(생성·검사·완료)만 표시한다. 가짜 퍼센트 없음.
- 로그 꼬리: Kiro 출력의 마지막 2줄(모노, 흐리게). 줄을 누르면 전체 로그 펼치기.
- 상단 요약 줄의 `동시 n개 실행 중 · 대기 m`은 실제 실행 중인 프로세스 수.
- `완료된 것부터 보기`: 하나라도 완료되면 활성. 화면 5로 가되 생성은 계속된다(미완료 카드는 상태로 표시).
- 전부 끝나면 자동으로 화면 5로 넘어가지 않고 버튼이 `비교하기 →`로 바뀐다.
- `전부 멈추기`: 확인 없이 즉시 모든 자식 프로세스 종료. 상태는 `멈춤`.

## 화면 5. 비교 격자 (핵심 화면)

```

│                   │ │                   │ │                   │
│  (실제 렌더,       │ │  (시안 실제 렌더)  │ │  (시안 실제 렌더)  │
│   축소 보기)       │ │                   │ │                   │
│                   │ │                   │ │                   │
├───────────────────┤ ├───────────────────┤ ├───────────────────┤
│ 원본              │ │ ✓ 14/14   2분 13초│ │ ⚠ 13/14  가격 누락│
│                   │ │                   │ │ ⚠ 지어낸 숫자 1    │
```

- 카드: 시안을 실제로 렌더한 격리 뷰를 축소해 보여 준다(데스크톱은 1440폭을 카드 폭에 맞춰 축소, 모바일은 390폭). 카드 안에서 세로 스크롤 가능.
- 원본 카드는 항상 맨 앞, 테두리 점선.
- 카드 아래 정보줄: 검사 결과 배지(`✓ 14/14` 또는 `⚠ 13/14`), 걸린 시간, 경고 꼬리표(`가격 누락`, `지어낸 숫자 1`, `콘솔 오류 2`). 실패 카드는 렌더 대신 사유와 `로그 보기`.
- 카드 열 수: 창 폭에 따라 3~4열(데스크톱), 모바일 모드에서는 5~6열(세로로 긴 카드).
- 데스크톱/모바일 전환은 모든 카드에 한꺼번에 적용.
- 스크롤 동기화 토글(`↕ 같이 스크롤`): 켜면 한 카드를 스크롤할 때 모든 카드가 같은 비율로 스크롤된다. 범위가 넘치면 가장 먼저 잘라 낼 기능.
- 카드 클릭 → 화면 6.
